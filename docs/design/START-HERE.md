# 新对话／Luna 接手入口

这份文件提供独立于旧聊天记录的编码上下文。用户将在新对话使用 Luna 实现；本文件不要求切换模型、调用子 agent 或重新讨论已确认架构。

## 1. 已确定的目标

在已有 Tools Touch 上增量实现 11 个用例：Gmail 登录；Pi 多 provider 登录；导师研究与论文阅读；邮件写作；用户确认发送；学校／学院招生窗口；学院背景与评价采集；学院推荐；学院导师完整目录采集；导师个性化排名；分析与投递数据记录。

用户补充：本地单人、单 Gmail；学校总览每校一行，校内学院／项目／批次表，Excel 每校一个 sheet；首轮 3—5 所计算机相关学校／学院；产品还应是类似飞书／Notion 数据库的表格记录器，支持自定义表／字段、关联、视图、批量编辑和全量导出。

技术约束：C# WPF＋SQLite；Pi 的 Node 适配使用 pnpm；Python 使用 uv。业务写入和邮件确认归 C#；Pi 负责认证／分析／写作，Python 负责来源适配。首版不增加服务端账号、云同步、任意 SQL 编辑或模型发送工具。

## 2. 开工阅读顺序

1. [实施状态](IMPLEMENTATION-STATE.md)：当前完成到哪里、下一工作包、已知环境问题。

3. [固定决策及文件迁移](03-implementation-map.md)：实施顺序、文件级入口、依赖与需要保留的行为。
4. 当前 Pxx 子计划及其引用的详细设计；需要跨进程或日期／表格接口时读[核心契约](04-contracts.md)。
5. [验收与证据](05-verification.md)：当前工作包的检查及预期结果。

无需开工前反复读完所有文件；P00 开始只需入口、状态、文件迁移的 P00 和 P00 子计划。后续每个工作包按链接展开。出现设计冲突先核对固定决策，修正文档再实施，不静默发明第三套协议。

## 3. 首个工作包怎么做

从 `P00-A` 开始：检查 `git status`、实际文件、工具路径与版本、旧测试入口；保存结果到本地 `artifacts/implementation/P00-A/`，在状态文档记录摘要。当前仓库不是空项目，也没有 `.sln` 基线。

然后执行 `P00-B` 的 pnpm 迁移，接着 uv 环境与打包脚本入口。P00 不做数据库 schema 或 Pi 协议升级；验证基线稳定后进入 P01。具体完成条件见[工作包表](03-implementation-map.md)。

设计会话最后检查时，Node 为 24.16.0、uv 为 0.9.17；`dotnet` 不在当前 Linux PATH，pnpm 路径指向 Windows 挂载盘。这只是环境观察，后续重新检查；不要假设已具备完整 Linux .NET／pnpm。已有文档曾记录 SDK 10.0.400 和 Windows 测试，不能直接把旧环境记录当成当前可运行证明。

同时有账户／代理功能在途修改，包含新增 AgentProxy.cs 和 agent-host/src/runtime.ts。先查看当前 diff 与文件，再按迁移职责处理；保留这些实现和测试，不将“旧基线”解释为需要恢复旧代码。

## 4. 未定项如何处理

| 项目 | 当前默认／下一步 | 是否阻塞开工 |
| --- | --- | --- |
| 经验和评价来源 Q3 | 草案按公开网页＋用户主动导入；先实现官方资料、导入接口与合成经验样本。自动访问登录社区等用户明确要求后做来源适配 | 不阻塞 P00—P03 或官方导师采集 |
| 首轮具体学校 | 用户还未指定名称；P03 先提供可编辑种子配置和合成 fixture。可提议北大、上交、浙大作候选，必须标为建议，学院及 URL 实际核实后登记 | 不阻塞离线实现；真实覆盖验收需明确种子 |
| com／A 会 | 暂按 committee 与版本化 CCF A 会议；存储支持其他口径，算法不写死未核实年份的目录 | 不阻塞字段／规则设计 |
| Gmail／搜索／模型配置 | 使用现有配置入口和测试替身；需要真实验收时使用用户在产品中配置的账号 | 不阻塞离线测试；真实验收缺口保留 |

用户后续答复优先于这里的暂定值。遇到一个来源、Windows 主机或账号缺失时，继续其他已授权工作，同时记录准确缺口；不伪造成功，也不把所有实施都停在这个问题上。

## 5. 每个工作包的交接记录

更新状态文档的工作包状态和事实：变更路径、迁移号／协议号、执行命令、结果、证据、已知问题、下一工作包。未完成时记录具体函数／文件和失败测试，避免下一次重做。

检查用合成数据与独立临时目录。原有正式用户数据、未跟踪 baoyan-cli、其他未提交修改都保留。新建 fixture 和接口不等于业务实现完成；只有入口连接、数据持久化及对应检查通过，才完成该工作包。
