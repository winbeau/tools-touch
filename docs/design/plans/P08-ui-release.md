# P08 界面整合、性能与 Windows 发布验收

状态：计划。前置：P03—P07。设计依据：[WPF 与交付](../details/06-desktop-delivery.md)。

## 编码范围

Desktop 导航与各 Features、Resources／Controls；Windows 原生回归；scripts/package.py／installer／verify／test-windows；CI 和发布／用户文档。

## 子步骤

1. 整合九个工作台入口、统一样式、数据刷新与选择保护；详情页／记录器导航保留上下文。
2. 检查 DataGrid 行列虚拟化、SQL 分页、查询取消、状态更新节流和导出内存占用。
3. 按约定硬件与合成负载测量 p95 查询、首屏、滚动／编辑响应和全量导出；失败后针对瓶颈调整索引与批次。
4. 原生 Windows 检查 DPI、键盘、空结果、绑定错误、DPAPI、长路径、休眠、关闭／重启恢复。
5. 生成包含 .NET／Node／Python 生产运行时的安装包，验证 pnpm 依赖不引用开发机 store、uv 环境正确打包。
6. 干净 Windows 用户执行安装、升级旧库、导出／备份恢复、卸载保留数据；构建清单含精确依赖与文件哈希。
7. 对 U01—U11 逐项收集证据；真实模型、学校来源和 Gmail 流程单独验收，不把模拟成功计入。

## 验收与退出条件

所有必要规则／数据库／子进程／原生检查通过；真实流程仍缺什么如实列出。用户可以从资料导入走到学院推荐、导师分析、确认联系与申请记录；也可单独管理和导出自定义表。确认后的发布候选有可复现安装包、备份策略和明确限制。

发布行为与此设计任务分开：本轮不构建或发布新版本。实际发布按届时用户授权执行，不能用文档中的“计划发布”视作对任意版本发布的授权。
