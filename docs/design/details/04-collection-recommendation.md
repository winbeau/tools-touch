# 采集、证据、学院画像与两级推荐

返回[详细设计](../02-detailed-design.md)。首轮为 3—5 所指定学校的计算机相关学院，之后扩展来源和批次；以下规则不依赖学校固定名单。

## 1. 来源接入与采集层次

来源范围 Q3 仍待确认；当前草案按“公开网页＋用户主动导入资料”设计。资料来源按用途分层，不能按单一网站可信度覆盖所有声明。

| 来源 | 用途 | 局限／记录方式 |
| --- | --- | --- |
| 学校／学院官网、研究生院公告 | 项目资格、报名时间、师资名单、公开结果 | 官方事实也要匹配年度和项目；镜像／旧公告可能失效 |
| 导师／课题组主页 | 研究方向、联系方式、公开招生、培养安排 | 主页存在不代表本年招生；保留最后核验时间 |
| arXiv／Crossref／论文官网 | 文献元数据、论文全文与作者线索 | 作者需要消歧；摘要不能冒充全文 |
| baoyan 聚合源 | 夏令营／预推免发现、报名与官网链接 | 不保证完整；未核验时标记聚合信息 |
| 公开经验、评价网页 | 历史背景样本、培养体验 | 选择偏差、匿名与转载；是第三方陈述 |
| 用户手动导入 | CV、成绩／排名、经验表、个人笔记 | 记录导入者／时间、文件行号及用户确认 |
| 飞跃导师参考快照 | 初始化导师身份和来源线索 | 已加工内容保留上游出处；过期招生与评价重新核验 |

首版静态公开 HTTP 复用现有 PublicWeb；JavaScript 渲染必要时由 Python 专用浏览器适配器读取。每种来源实现自己的分页、链接发现和字段抽取，不使用一个万能页面提示词承担全部采集。

来源适配器契约包含 `SourceId / AdapterVersion / DiscoverScope / Enumerate / Fetch / Parse / Normalize / Health`；页面解析返回候选 DTO 与定位证据，不直接提交业务实体。采集限制来自来源策略，HTTP、跳转、体积和连接安全沿用应用受控抓取逻辑。

## 2. 学院全部导师采集

完整性以学院官方师资目录为起点：

1. 登记 School／Department／校区与目录种子 URL，确认“在职师资、兼职、博士后”等范围。
2. 遍历分页、研究所／系分类、首字母索引及合法站内子目录；保存发现队列和父页面来源。
3. 规范化目录条目与主页链接，记录姓名、任职、原始文本；不会因为没有邮箱就丢弃导师。
4. 按导师子任务抓取主页／课题组／招生页，提取带引用的结构化候选。
5. 先做实体消歧，再补论文和本年招生；评价是独立可选来源步骤。
6. 发布采集清单：已发现／解析成功／主页失败／目录失败／待身份核实／跳过数量和原因。

`CoverageState` 为 CompleteForDeclaredSources／Partial／UnknownDenominator。目录未给总人数时不能显示“100% 学院导师”；可以显示“已遍历 4 个已知目录、发现 186 个条目、成功解析 173 位”。目录失败时保留旧数据和失败清单。

全量刷新与增量更新都保存快照。页面消失不删除导师，标记来源不可访问／任职待核实；连续失联也不自动断定离职。不同目录重复出现同一人合并任职关系，保留原条目映射。

## 3. 身份消歧和证据准入

优先顺序：来源稳定 ID／已确认 canonical URL→ORCID 等可靠标识→姓名＋任职＋邮箱／主页多项一致→人工核实。同名、主页迁移、跨校流动、联合培养分别覆盖。不能按姓名全局唯一，也不能仅凭作者同名关联所有论文。

邮箱只取明确公开的地址或可无歧义还原的 `name [at] university [dot] edu`，保存还原规则和原文；推测邮箱不能自动成为可发送收件人。最终发送仍由用户核对。

每个 EvidenceClaim 保留原始来源、定位、抽取版本、发生年度、来源类别和核验状态。模型得到的“可能强 committee”“可能不招硕士”记 ModelInference；没有招生声明记 Unknown，而非 No。

评价按事实主张和体验主张分开。例如“官网列出硕士招生”与“匿名评价说不允许实习”分别呈现；后者显示来源类别、发布日期和未核实标记。转载同一帖子通过内容哈希／引用链去重，不当作多份独立佐证。相互矛盾的评价并列，不自动合成肯定的正面／负面人格标签。

## 4. 学院画像与 bar 统计

`CommitteeMode` 暂按招生决策解释：Strong 为学院统一筛选主导，Weak 为导师意见影响较大，Mixed 为阶段／项目不同，Unknown 为资料不足。用户可自定义解释备注；不能由学校档次或一个导师的回复反推整院制度。

学院画像至少包括：正式资格条件、筛选／面试方式、是否需提前联系导师、committee 证据、公开招生名额、学位项目、背景样本和时间适用范围。

bar 保存为多维向量与分布：本科类别、专业／跨专业、排名类型与比例、GPA 及满分、英语类型与分数、科研经历、论文等级／顺位／状态、竞赛和录取阶段。不同学校的 GPA 不直接平均；排名保留专业／学院范围、人数与学期；排名比例不可只存“前 10%”失去定义。

| 指标 | 统计规则 |
| --- | --- |
| 985 分布 | 分母为同年同项目同阶段、有已知本科类别的去重样本；同时展示总样本 N 与未知类别数 |
| rk x% | 限相同排名口径，展示中位数／分位区间及样本量；排名越小越靠前 |
| A 会篇数 | 分类目录及版本固定；会议／期刊分开；一作／共一／其他、已接收／已发表／投稿中分别统计 |
| 平均 bar | UI 展示“历史样本背景分布”，优先多维分位数，不压成一个伪精确门槛 |
| 录取／入营情况 | 入营、优营、预录取、最终录取分层，不把入营者当最终录取者 |

缺失论文数量不记零；自述“无论文”才是已知零。录取名单未提供本科信息时，不靠姓名推断籍贯／学校。小样本默认阈值设为 10，低于阈值显示样本不足，可看个例但不标为稳定分布；该阈值是初始产品规则，后续依据验证调整。样本自选择偏差即使 N 较大也要保留说明。

`StatisticsBuilder` 只处理可比较的样本组，输出分母、缺失数、去重方案、指标定义版本和引用 ID。模型可解释分布，不能凭空补充样本数字。

## 5. 用户资料与需求理解

CV 导入后先提取候选事实，由用户确认本科院校／专业、毕业或申请周期、排名分子分母、GPA 满分、语言成绩、论文及研究经历。原文、抽取候选和确认事实分别存；原始 CV 文件哈希固定。

可选提示词如“想做大模型，不接受直博，希望允许实习”解析成研究方向、学位、地域、职业倾向、培养偏好等约束。每项注明硬约束／软偏好／不明确；存在歧义展示给用户编辑，不悄悄把一句偏好变成淘汰条件。没有提示词时按已确认资料和默认权重运行。

跨模型传递的是任务需要的确认事实；一般排名／推荐无需把完整附件和联系方式发给所有模型。每次任务展示所用 provider 和资料版本。

## 6. 学院／项目推荐

目标为学院内项目及目标申请年度。输出可以按学校聚合，底层条件不混淆学硕、专硕和直博。

第一步是硬资格三态：Eligible、Ineligible、NeedsVerification。只有可靠本年条件与已确认用户事实发生明确冲突才判 Ineligible；没有英语分数、招生条件缺失等进入 NeedsVerification。第三方 bar 和导师评价不得用作正式资格淘汰依据。

第二步对全部候选用相同规则形成分项：

| 学院分项 | 初始权重 | 输入 |
| --- | --- | --- |
| 方向与项目适合度 | 0.30 | 项目方向、导师群体、用户研究／培养目标 |
| 背景适配 | 0.25 | 确认背景与可比较样本；样本不足标未知 |
| 用户偏好 | 0.20 | 地区、学位、培养、职业偏好 |
| 机会可操作性 | 0.15 | 本年窗口、明确仍可报名与材料准备情况 |
| 招生方式适配 | 0.10 | committee、是否需联系、用户联系意愿 |

评分表达建议优先级，不是录取概率。冲刺／适配／相对稳妥可以作为基于背景分布的策略标签，必须注明样本依据；没有足够证据则显示无法判断，绝不承诺“保底一定录取”。

## 7. 海量导师推荐

导师候选首先限定学校／学院／项目、任职有效期、学位与申请年度。明确本年不招生且目标匹配的记录放入“不适用”分组；招生未知保留在“待确认”分组，用户可筛选。论文方向很近不自动补成招收用户目标学位。

流程分三层，任务中心显示每层覆盖人数：

1. **全部候选基础评分**：结构化标签、关键词／FTS、任职、学位、公开研究摘要；不用给每位导师读几十篇论文。
2. **统一候选集语义评估**：默认对前 200 名执行分批 Pi 评估，保留用户指定必看对象、方向多样性候选及少量未高分样本，降低关键词召回偏差；每条独立输出有引用的分项，不让模型一次对几万个人自由排序。
3. **重点研究**：默认前 20 名进行方向核验，每人最多 3 篇论文、按页限额读取，生成更充分的分析；用户可以扩大范围和预算。

200／20／3 是可配置初值，不是质量保证。语义评估排名仅在同一评估规则、预算与输入完整度条件下比较；UI 区分“全库基础排名”“已语义评估候选排名”“重点研究结果”，不把未研究者显示成已经深度比较后的最后一名。所有排名保留 candidate scope。

| 导师分项 | 初始权重 |
| --- | --- |
| 研究方向匹配 | 0.35 |
| 用户科研／技能与导师项目匹配 | 0.20 |
| 目标年度及学位的招生证据 | 0.20 |
| 培养方式与用户偏好 | 0.15 |
| 用户地域／机构／其他偏好 | 0.10 |

硬学位约束已在资格层判断，不再用软评分抵消。评价缺失不降低人格评价；匿名体验可作为偏好待核实项，必须带来源。强 committee 学院的说明应强调学院资格的重要性，但不能武断改变导师招收能力。

## 8. 分数、未知值与稳定重排

各已知分项为 0—1，权重总和为 1。规则分数由 C# 计算；模型只提供符合 rubric 的分项观察，例如 0／0.25／0.5／0.75／1 及引用。没有引用或无法解释则分项为未知。

对已知分项集合 K：`knownScore = 100 × Σ(wᵢsᵢ) / Σ(wᵢ)`；`coverage = Σ(wᵢ)`。K 为空时 score=null。未知分项不是实际 0，而是区间 [0,1]，因此还给出 `lower = 100 × Σ(known wᵢsᵢ)`、`upper = lower + 100 × Σ(unknown wᵢ)`。区间表示评分不确定范围，不是概率置信区间。

初始排序先按资格分组；coverage < 0.6 的候选放“资料不足”组。足够证据组按保守下界、knownScore、来源质量分级、稳定 ID 排序，展示 coverage 及上下界，解释为何信息不足时不进入高可信前列。允许用户改看“已知匹配分”，保存为不同视图。0.6、权重和 rubric 均版本化，待首轮样本调校。

每个 RecommendationItem 返回：目标、资格结果、排名范围、分项、理由、冲突、未知项、来源、下一步建议，以及 ProfileVersion／PreferenceVersion／DatasetRevision／Model／PromptVersion／AlgorithmVersion。重新分析生成新 run，可以对比排名变动由新资料、公告更新还是权重变化造成。

## 9. 研究与写作衔接

方向摘要必须分别呈现“主页长期方向”“近年已核验论文主题”“与用户经历相关点”。论文结果记录 Abstract／Pages／FullText 和实际页码；扫描失败标 Unreadable，不写“已阅读全文”。

用户从任意候选进入研究，不要求必须进入推荐前列。草稿使用选定分析 artifact 及资料版本，引用可核实的方向契合点；只有摘要时措辞为“了解到该工作／阅读摘要”，不能声称深入读完全文。

## 10. 质量验收

用首轮学校建立版本化人工核对集：目录覆盖、同名消歧、邮箱出处、年度招生、论文归属、bar 分母和推荐理由。记录 Recall@K／NDCG@K 等相对人工相关性指标前，先明确人工标签与候选池；没有标注集不报告虚构准确率。

必要回归：未知资格不被淘汰、去年招生不沿用、录取与入营不混合、转载样本去重、没有论文≠论文未知、同名论文不误归属、提示词硬约束生效、权重归一、资料不完整组可见、同输入排序稳定、不同深读覆盖不混成同一榜单、恶意网页指令不能触发邮件或越权文件访问。
