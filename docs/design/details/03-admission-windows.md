# 招生年度与窗口判定

返回[详细设计](../02-detailed-design.md)。本模块必须独立于 LLM 实现为可测试的 C# 规则；模型可以抽取日期，不直接决定“开放／结束”。

## 1. 四种时间含义

| 概念 | 示例 | 使用方式 |
| --- | --- | --- |
| CycleYear | 2026 年进行夏令营／预推免 | 用户工作区当前申请年度，默认本地业务日期所在年，可切换 |
| EntryYear | 2027 级研究生 | 单独记录，不能直接当作 2027 年报名 |
| SourceYear | baoyan 网站 year=2025 | 原样保留，需和公告正文校验 |
| FetchedAt／PublishedAt | 2026-09-05 抓取／2025-09-01 发布 | 抓取与发布时间不同，不替代招生年度 |

业务时间默认 Asia/Shanghai；机器在美国时区运行也按公告时区判断报名窗口。底层使用 `DateOnly`、`DateTimeOffset` 和时区解析适配，不能直接把无时区字符串转成机器本地 DateTime。

## 2. 判定结果是多个维度

`WindowAssessment` 至少包含 TargetCycleYear、ActualState、ActualBasis、EstimatedPhase、SourceYear、OriginalRange、ProjectedRange、Confidence、MissingFacts、AsOf、RuleVersion。

| 维度 | 取值 |
| --- | --- |
| ActualState | NotStarted／Open／Closed／Cancelled／Unknown／Conflict |
| ActualBasis | CurrentOfficial／CurrentAggregator／UserVerified／NoCurrentEvidence |
| EstimatedPhase | NotAvailable／Upcoming／WithinEstimatedRange／EstimatePassed／Unprojectable |

UI 将状态和依据组合显示：“未开始·今年官网已发布”“开放中·聚合源，待核实”“预计未开始·参考 2025”“预计区间已过·今年尚未确认”。历史原记录仍可以在历史视图显示已结束；不能拿它的结束状态填到今年总览。

本年有效官方公告优先于历史预测；不同官方公告先按适用项目／批次区分，再判断更新或延期是否明确取代旧公告。两个同级来源矛盾且无法判断覆盖关系时显示 Conflict，不能机械挑最新抓取的一条。

## 3. 本年实际状态规则

将日期转换成边界及精度；使用半开区间 `[start, endExclusive)` 表达应用统一计算规则。原文明确边界时按原文；只写日期的截止约定为该日结束，界面显示“截止时刻未公布”，这是一项产品解释，不是声称官网给出了 23:59:59。

| 已知信息 | 判断 |
| --- | --- |
| 本年已明确取消该批次 | Cancelled |
| 有开始／截止且当前早于开始 | NotStarted |
| 有开始／截止且 start ≤ now < endExclusive | Open |
| 有可信截止且 now ≥ endExclusive | Closed，即使开始未知 |
| 只有未来开始 | NotStarted；过了开始但无截止／“持续开放”说明则 Unknown |
| 只有未来截止 | Unknown，可显示“距已公布截止 X 天，开始时间待核实” |
| 正文明确“现已开放”，仍在有效期且没有关闭证据 | Open；记录该措辞对应的声明和校验时间 |
| 只公布活动日期 | 报名状态 Unknown，活动日期单独显示 |
| 日期无法解析 | Unknown，进入待核实 |
| 开始晚于结束 | Conflict，reason=INVALID_DATE_RANGE，进入待核实 |

模糊日期使用可能边界：早于最早可能开始才能确定未开始，晚于最晚可能截止才能确定结束；只有晚于最晚可能开始且早于最早可能截止才可判定开放。其余显示 Unknown。首版“9 月中旬”等文本可只保留原文而不生成精确倒计时。

## 4. 历史投影规则

仅当同一学院／项目／活动类型／可识别批次缺少本年适用信息时启用历史参考。不要把夏令营窗口投影到预推免，也不要用全校日程覆盖某个学院的独立日程。

首版使用最近一个已确认历史 CycleYear 的同月同日投影；投影不是直接 `AddYears(1)`，应按 `targetYear - sourceCycleYear` 平移，各边界相对活动年度的年份偏移保持不变。这样跨年窗口仍可以跨到下一年。不存在的日期（如非闰年 2 月 29 日）、年度歧义或批次无法对应时标 Unprojectable，保留原文并请求人工核实。

多年度估计后续可在相同项目和稳定批次下计算月份日期分布，但首版不把不同来源／项目的时间平均成假窗口。若采用多年度模型，须新增 MethodVersion、样本数和估计范围。

预测阶段同样采用半开区间：now < projectedStart 为 Upcoming；projectedStart ≤ now < projectedEndExclusive 为 WithinEstimatedRange；now ≥ projectedEndExclusive 为 EstimatePassed。只有一个边界时仅显示“预计开始／预计截止”，不能据此猜另一边界或标记整个预计窗口开放。可执行输入／期望见[窗口 fixture](../fixtures/window-cases.json)，更正优先级与状态有效期见[核心契约](../04-contracts.md)。

**任何 EstimatedPhase 都不使 ActualState 变为 Open／Closed。** 缺少本年事实时 ActualState=Unknown、ActualBasis=NoCurrentEvidence；“预计区间已过”之后继续提示待确认，不自动移入实际结束列表。

## 5. 用户例子与边界验收表

以下均为合成验收输入。

| 输入 | 判断时刻／目标年度 | 预期展示 |
| --- | --- | --- |
| 仅有 2025-09-12—09-18 | 2026-09-05，目标 2026 | **预计未开始**，预计 2026-09-12—09-18；本年尚无公告；保留原 2025 日期 |
| 同一历史记录 | 2026-09-15 | 预计窗口内，需核实今年公告；不是实际 Open |
| 同一历史记录 | 2026-09-20 | 预计区间已过、今年待确认；不是实际 Closed |
| 本年官网 2026-09-12—09-18 | 2026-09-05 | 未开始·今年官网已发布 |
| 本年官网同上，截止仅精确到日 | 2026-09-18 20:00 上海时间 | 按日级约定开放，显示截止时刻未公布 |
| 本年官网同上 | 2026-09-19 00:00 上海时间 | 已结束 |
| 本年官网截止 09-18 17:00，约定该时刻关闭 | 09-18 17:00 上海时间 | 已结束；精确时刻边界测试 |
| 历史 09-12—09-18，但本年官网 09-01—09-03 | 2026-09-05 | 已结束，以本年官网为准 |
| 标题“2027 级”，正文报名 2026-09-12 | 目标 2026 | CycleYear=2026，EntryYear=2027 |
| 网站 year=0，只有抓取时间 | 目标 2026 | 年度待确认，不归入 2026 已结束或未开始 |
| 仅有活动日期 09-20—09-22 | 09-15 | 报名时间待核实 |
| 第一批已结束，第二批未开始 | 目标 2026 | 两条批次保留；学院显示“有待开放批次” |
| 官网明确延长截止至 09-25 | 09-20 | 新观察取代对应旧截止，保留变更来源与历史 |
| 历史跨年 2025-12-28—2026-01-03，周期 2025 | 目标 2026 | 预测 2026-12-28—2027-01-03 |
| 历史边界 2024-02-29，目标非闰年 | 目标 2026 | Unprojectable，不静默改成 02-28 |
| 相同目标运行在洛杉矶时区机器 | 与上海同一时刻 | 与上海业务时间判断一致 |

## 6. 学校总览与学院行聚合

学校总览按 `SchoolId` 一行，统计本年不同学院／项目／批次的实际开放数、实际未开始数、历史预测数、已结束数和待核实数。重点摘要优先显示“有开放窗口”，其次“有即将开放窗口”，然后“有历史预测”；各计数始终可见。

只有已纳入该学校视图的有效本年轮次均明确结束／取消、且没有未知轮次时，才可显示“已收录批次均结束”，同时显示采集覆盖范围。不能从一个学院截止推出整所学校全部结束。

进入学校后的默认行粒度为 `Department × Program × Round`；同一学院有多行可折叠分组。字段包括学院、项目／学位、类型／批次、本年实际报名窗口、历史参考、预计窗口、状态、官网、报名链接、最新核验、我的投递。

## 7. 缓存、更新和提醒

状态是 `观测版本＋规则版本＋目标年度＋asOf` 的派生结果，不长期保存单个“已过期”布尔值。跨上海午夜、精确开始／截止、系统恢复休眠、切换年份和新公告入库时重新计算。Reminder 绑定事实或预测依据；历史预测提醒标题必须有“预计”。

`CycleResolver` 负责年度解释；`WindowEvaluator` 是纯规则；`AdmissionQueryService` 聚合学校行；`AdmissionRefreshJob` 负责更新来源；`ReminderService` 安排应用运行时提醒。UI、导出和推荐统一调用同一个评估器，避免三套日期算法。
